# КР №2 — JavaFX-блог-платформа

Требования прочитаны 10 октября 2026 года на [странице КР №2](https://online-edu.mirea.ru/mod/assign/view.php?id=933004).
Срок на странице: 1 ноября 2026 года, 13:56. В задании указана команда из четырёх человек; ранее в нашей команде было три, поэтому состав нужно согласовать с преподавателем.

## Запуск на этом Mac

```bash
cd ~/Desktop/blog-platform
./run.sh
```

Скрипт выбирает установленную Java 21 для этого запуска. PostgreSQL из КР №1 должен работать на порту 5432.
В IntelliJ IDEA выберите Project SDK 21 и Maven JDK 21, затем запустите `ru.mirea.blogplatform.fx.BlogPlatformApplication`.
На Windows с настроенными Java 21 и Maven 3.9+ выполните `mvn javafx:run` или `./run.ps1`.
Консоль КР №1 сохранена как дополнительный способ запуска: `mvn compile exec:java`.

## Настройки PostgreSQL

`src/main/resources/database.properties` содержит адрес и имя пользователя базы КР №1. Пароль в Java-классы не записывается.
Локальные настройки можно задать в `database.local.properties` (пример рядом в корне проекта). Этот файл игнорируется Git.
Переменные `BLOG_DB_URL`, `BLOG_DB_USER`, `BLOG_DB_PASSWORD` имеют приоритет над файлами.
Другой файл конфигурации можно выбрать переменной `BLOG_DB_CONFIG` или системным свойством `blog.db.config`.

Если создаёте базу заново, примените `src/main/resources/db/schema.sql` и `seed.sql`.
Для существующей базы КР №1 таблицы и бизнес-правила остаются теми же. Приложение читает и изменяет именно эти данные.

## Что показывать на защите

1. Запустите окно. На вкладке «Публикации» находятся `TableView`, поиск по заголовку/тексту/адресу/автору, фильтры статуса, автора и диапазона дат создания.
2. Нажмите «Добавить публикацию». Выберите автора из `ComboBox`; ID вручную вводить не нужно. Сохраните черновик.
3. Выберите строку и откройте «Изменить»: поля уже заполнены. Сохраните изменения и убедитесь, что таблица обновилась.
4. Откройте «Читать» для полного текста. Покажите смену статуса: черновик → проверка → опубликована → архив.
5. Проверьте ошибочный ввод: пустой заголовок/текст, повторный адрес, заголовок длиннее 200 символов. Форма показывает понятную ошибку и остаётся открытой.
6. Покажите совместную работу поиска и фильтров. Сбросьте фильтры. Нажмите заголовки «Создано» и «Заголовок»: повторные клики меняют направление сортировки. Shift-клик добавляет второй параметр сортировки.
7. На вкладке «Авторы» покажите CRUD, роли, поиск по имени/email и сортировки. Удаление автора с публикациями или комментариями блокируется связями БД.
8. На вкладке «Комментарии» выберите публикацию и автора из списков, создайте комментарий, измените текст и выполните модерацию. Доступны поиск, фильтры и сортировки.
9. Откройте «Статистика»: всего публикаций, опубликованных, черновиков, авторов с публикациями, средняя длина текста. График показывает распределение по статусам. Статистика относится ко всей базе.
10. Вернитесь к таблице, задайте фильтр и нажмите «Экспорт текущего списка». Через `FileChooser` выберите XLSX или CSV. В файл попадают видимые строки активной таблицы в текущем порядке.
11. Удалите только демонстрационную запись: программа запросит подтверждение. При удалении публикации её комментарии удаляются каскадно, об этом предупреждает диалог.

## Файлы и ответственность

| Уровень | Файлы |
|---|---|
| Запуск | `fx/BlogPlatformApplication.java`, `fx/AppContext.java` |
| View | `resources/fx/main.fxml`, `posts.fxml`, `users.fxml`, `comments.fxml`, `statistics.fxml` |
| Формы | `resources/fx/post-form.fxml`, `user-form.fxml`, `comment-form.fxml` |
| Controller | `fx/controller/*Controller.java`, `fx/form/*Controller.java` |
| Общая работа таблиц | `fx/controller/TableController.java`: ObservableList → FilteredList → SortedList → TableView |
| Бизнес-правила | `service/BlogPostService.java`, `UserService.java`, `CommentService.java` |
| Поиск и совмещённые фильтры | `service/CatalogQueryService.java` |
| Статистика и экспорт | `service/StatisticsService.java`, `TableExportService.java` |
| Repository / JDBC | `repository/` и `repository/jdbc/` |
| Подключение | `config/DatabaseManager.java`, `resources/database.properties` |
| Фоновые операции | `fx/FxTasks.java`: JavaFX Task и один рабочий поток для JDBC/экспорта |
| Оформление | `resources/fx/blog.css` |

При `FXMLLoader.load()` элементы с `fx:id` связываются с полями контроллера, отмеченными `@FXML`.
`onAction="#add"` у кнопки вызывает метод `add()` контроллера.
`Stage` — окно, `Scene` — содержимое окна, `Node` — элемент интерфейса.
`ObservableList` уведомляет таблицу об изменении списка; после CRUD приложение получает новый снимок данных для всех вкладок.
Сортировка `TableView` задаёт Comparator, с которым связан `SortedList`. Фильтрация работает через предикат сервиса.
SQL находится в JDBC-репозиториях; обработчики кнопок координируют интерфейс и вызывают сервисы.

## Проверка

Результаты последнего запуска и оставшиеся ограничения: [kr2-verification.md](kr2-verification.md).

```bash
JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home mvn clean test
```

Для проверки JDBC укажите отдельную тестовую базу с применёнными SQL-скриптами:

```bash
BLOG_TEST_DB_URL=jdbc:postgresql://localhost:5432/blog_platform_test \
BLOG_TEST_DB_USER=postgres BLOG_TEST_DB_PASSWORD='' \
JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home mvn test
```

FXML-тест выполняется при доступном графическом окружении. На сервере без дисплея используйте Xvfb или проверяйте интерфейс на рабочем компьютере.

## Docker

Согласно заданию, нужно развернуть преподавательский пример (PostgreSQL + Spring Boot backend + веб-часть) и запустить его JavaFX-клиент.
Это отдельная демонстрационная система. Наша КР №2 обращается по JDBC прямо к PostgreSQL из КР №1.
Порядок развертывания примера описан в [docker-reference.md](docker-reference.md).

Для новой локальной базы нашей платформы также предусмотрен `compose.yml`. Скопируйте `.env.example` в `.env`, задайте пароль и выполните:

```bash
docker compose up -d --wait
```

База будет на `localhost:55433`. В настройках JDBC укажите этот порт и пароль из `.env`.
SQL-скрипты инициализируют только новый Docker volume. Существующие данные локальной базы в Docker автоматически не переносятся.
При переносе существующей БД используйте `pg_dump` и восстановление в контейнер, чтобы сохранить данные КР №1.
Остановка: `docker compose down`, без удаления volume.
