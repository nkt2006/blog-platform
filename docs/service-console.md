# Сервис и консольное меню

## Что реализовано

`ConsoleUi` показывает циклическое меню и передаёт действия в `BlogPostService`. Сервис работает через интерфейсы `BlogPostRepository` и `UserRepository`, которые реализованы JDBC-классами. Консоль не содержит SQL.

В меню есть создание, список, получение по ID, изменение, удаление, поиск по заголовку и имени автора, фильтры по статусу и автору, сортировки по дате создания и заголовку, смена статуса, статистика, список авторов и экспорт в Excel. Текст вместо числа, неправильный статус, отсутствующий ID и ошибки репозитория выводятся как сообщение; цикл меню продолжается.

## Правила публикаций

1. Заголовок не может быть пустым.
2. Текст не может быть пустым, в том числе при публикации.
3. Автор должен существовать.
4. Адрес публикации (`slug` в коде и БД) обязателен, приводится к нижнему регистру и должен быть уникальным. Допустимы буквы, цифры и дефисы между словами.
5. Новая публикация получает статус «Черновик» (`DRAFT`). Разрешены только переходы «Черновик» → «На проверке» → «Опубликована» → «В архиве». В Java и PostgreSQL им соответствуют `DRAFT → REVIEW → PUBLISHED → ARCHIVED`.
6. `publishedAt` равен `null` до перехода в `PUBLISHED`, устанавливается в момент этого перехода и сохраняется при архивировании.

Сервис также сохраняет `createdAt` при изменении поста. Поиск, фильтры, сортировки и статистика используют Stream API поверх данных репозитория. Для учебного набора из 10+ публикаций этого достаточно.

## Статистика

Показываются пять показателей: всего публикаций, опубликованных, черновиков, авторов с публикациями и средняя длина текста в символах.

## Подключение компонентов

`Main` создаёт JDBC-реализации обоих интерфейсов и передаёт их в `BlogPostService`. Сервис использует `ExcelExporter` для сохранения данных; консоль вызывает его через сервис. Тесты сервиса используют временные реализации репозиториев только для проверки логики без БД.
