# Ветка `feature/service-console`

## Что реализовано

`ConsoleUi` показывает циклическое меню и передаёт действия в `BlogPostService`. Сервис работает через интерфейсы `BlogPostRepository` и `UserRepository`; конкретные JDBC-классы будут подключены после объединения веток. Консоль не содержит SQL.

В меню есть создание, список, получение по ID, изменение, удаление, поиск по заголовку и имени автора, фильтры по статусу и автору, сортировки по дате создания и заголовку, смена статуса, статистика и список авторов. Текст вместо числа, неправильный статус, отсутствующий ID и ошибки репозитория выводятся как сообщение; цикл меню продолжается.

## Правила публикаций

1. Заголовок не может быть пустым.
2. Текст не может быть пустым, в том числе при публикации.
3. Автор должен существовать.
4. `slug` обязателен, приводится к нижнему регистру и должен быть уникальным. Допустимы буквы, цифры и дефисы между словами.
5. Новый пост получает статус `DRAFT`. Разрешены только переходы `DRAFT → REVIEW → PUBLISHED → ARCHIVED`.
6. `publishedAt` равен `null` до перехода в `PUBLISHED`, устанавливается в момент этого перехода и сохраняется при архивировании.

Сервис также сохраняет `createdAt` при изменении поста. Поиск, фильтры, сортировки и статистика используют Stream API поверх данных репозитория. Для учебного набора из 10+ публикаций этого достаточно.

## Статистика

Показываются пять показателей: всего публикаций, опубликованных, черновиков, авторов с публикациями и средняя длина текста в символах.

## Подключение после merge

Точка входа должна создать JDBC-реализации обоих интерфейсов, передать их в `BlogPostService`, затем вызвать `new ConsoleUi(service, new Scanner(System.in), System.out).run()`. После подключения Excel-экспорта в меню нужно добавить команду экспорта. Тесты сервиса используют временные реализации репозиториев только для проверки логики без БД.
