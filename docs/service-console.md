# Сервис и консольное меню

## Что реализовано

`ConsoleUi` показывает главное циклическое меню и передаёт действия с публикациями в `BlogPostService`. Пункты 16 и 17 открывают отдельные меню `UserConsoleUi` и `CommentConsoleUi`; они обращаются к `UserService` и `CommentService`. Сервисы работают через интерфейсы репозиториев, которые реализованы JDBC-классами. Консоль не содержит SQL.

В меню есть создание, список, получение по ID, изменение, удаление, поиск по заголовку и имени автора, фильтры по статусу и автору, сортировки по дате создания и заголовку, смена статуса, статистика, список авторов и экспорт в Excel. Текст вместо числа, неправильный статус, отсутствующий ID и ошибки репозитория выводятся как сообщение; цикл меню продолжается.

Меню авторов и комментариев также содержат CRUD, поиск, фильтры и сортировки в обоих направлениях. Авторы фильтруются по роли и сортируются по имени/email. Комментарии фильтруются по статусу и публикации, сортируются по дате/тексту. Для каждого типа есть отдельное перечисление статусов или ролей и своё исключение.

## Правила публикаций

1. Заголовок не может быть пустым.
2. Текст не может быть пустым, в том числе при публикации.
3. Автор должен существовать.
4. Адрес публикации (`slug` в коде и БД) обязателен, приводится к нижнему регистру и должен быть уникальным. Допустимы буквы, цифры и дефисы между словами.
5. Новая публикация получает статус «Черновик» (`DRAFT`). Разрешены только переходы «Черновик» → «На проверке» → «Опубликована» → «В архиве». В Java и PostgreSQL им соответствуют `DRAFT → REVIEW → PUBLISHED → ARCHIVED`.
6. `publishedAt` равен `null` до перехода в `PUBLISHED`, устанавливается в момент этого перехода и сохраняется при архивировании.

Сервис также сохраняет `createdAt` при изменении поста. Поиск, фильтры, сортировки и статистика используют Stream API поверх данных репозитория. Для учебного набора из 10+ публикаций этого достаточно.

## Статистика

Показываются пять показателей: всего публикаций, опубликованных, черновиков, авторов с публикациями и средняя длина текста в символах.

## Правила авторов и комментариев

- Имя автора и email обязательны, email должен иметь корректный формат и быть уникальным.
- Комментарий может ссылаться только на существующую публикацию и существующего автора; его текст не может быть пустым.
- Новый комментарий получает статус `PENDING`. Затем его можно одобрить (`APPROVED`) или отклонить (`REJECTED`); повторная смена статуса запрещена.
- Удаление автора с публикациями или комментариями блокируется внешними ключами PostgreSQL. При удалении публикации её комментарии удаляются автоматически (`ON DELETE CASCADE`).

## Подключение компонентов

`Main` создаёт три JDBC-репозитория и три сервиса. `BlogPostService` использует `ExcelExporter` для сохранения данных с трёх листов; консоль вызывает его через сервис. Модульные тесты сервисов используют временные реализации репозиториев; интеграционные тесты проверяют JDBC на отдельной PostgreSQL-базе.
